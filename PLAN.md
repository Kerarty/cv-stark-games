# Интерактивное резюме для Stark Games — План

**Автор роли:** геймдизайнер, инициативное отклик (открытых вакансий нет → резюме уходит на hr@stark.games)
**Цель:** за 30–60 секунд показать HR и лиду, что кандидат — геймдизайнер, который знает портфолио студии, умеет маппить механики на контент и любить их игры не на словах.

---

## 1. Концепция: «Испытание кандидата» — резюме-путешествие по играм студии

Одно интерактивное резюме, собранное из трёх миров — по одному на каждую игру Stark Games.
Мета-рамка: кандидат проходит «испытание при приёме в гильдию», путешествуя по мирам игр студии. Каждая игра = своя механика, свой визуальный стиль и свой блок резюме.

```
[Хаб: Портал студии]
   ├── Мир 1. «Грани Реальности»  → опыт и навыки (RPG-формат)
   ├── Мир 2. Tile Seasons        → инструменты и проекты (match-3)
   └── Мир 3. «Ёлочка»            → контакты и финал (социальная сцена)
```

### Мир 1. «Грани Реальности» (браузерная MMORPG) — блок «Опыт и навыки»
- **Лист персонажа:** класс (геймдизайнер), уровень (годы опыта), гильдии (места работы).
- **Статы = навыки:** системный дизайн, баланс, нарратив, прототипирование, аналитика, инструменты. Каждый стат при наведении/тапе — обоснование «почему столько» (пример из практики).
- **Журнал квестов = опыт работы:** выполненные квесты (проекты) с наградами (результаты, метрики).
- **Достижения = ключевые успехи:** «Гейм-дизайн от А до Я», «Метрика улучшена на N%» и т.п.

### Мир 2. Tile Seasons (match-3) — блок «Инструменты и проекты»
- **Мини-механика на 30–60 секунд:** собираешь комбинации тайлов — каждый собранный «матч» открывает карточку: инструмент (Unity, Excel/Figma, плагины) или проект из портфолио.
- Проекты — как «бонусные уровни»: тап → карточка с задачей, решением, результатом.
- Это одновременно и контент, и демонстрация: геймдизайнер понимает, из чего состоит их жанр (цели уровня, ходы, бустеры).

### Мир 3. «Ёлочка» (социальная новогодняя игра) — блок «Контакты и финал»
- Финальная сцена в теплом праздничном стиле: «укрась ёлку» — каждый шар/подарок = контакт или артефакт (email, портфолио, PDF-резюме, ссылки на игры/прототипы).
- Кнопка-«подарок»: скачать классическое PDF-резюме (для тех, кто не играет).
- Пасхалка: короткая «открытка» — 3 предложения, почему именно Stark Games.

### Сквозная фишка: «Режим дизайнера»
Глобальный тумблер «как игрок / как дизайнер». Во втором режиме у каждой секции показывается дизайн-обоснование: почему эта механика, какая задача, какой эффект. Это главный аргумент для GD-позиции — резюме само объясняет свои решения.

## 2. Что это демонстрирует (маппинг на компетенции GD)

| Чего смотрит работодатель | Где видно в резюме |
|---|---|
| Знание портфолио студии | Вся структура построена на их трёх играх |
| Проектирование механик | Каждый блок = механика, оправданная контентом |
| Дизайн-мышление и аргументация | «Режим дизайнера» с обоснованиями |
| Понимание F2P и их жанров | Мир 2 сделан по канонам match-3 |
| Нарратив и подача | Мета-рамка «испытание в гильдию» |
| Уважение к времени людей | Тайминг 3–5 минут, skip-кнопки, PDF-fallback |

## 3. Техническая реализация

**Рекомендация: одностраничное веб-приложение** (HTML/CSS/JS, мини-матч на Canvas).
Почему не Unity WebGL: грузится 20–50 МБ и не запускается на части рабочих машин/телефонов — риск, что HR просто не дождётся. Веб открывается мгновенно, работает на мобиле, легко хостится.

- Хаб и миры — секции одной страницы с переходами-анимациями (или SPA с экранами).
- Матч-3 — компактный Canvas-модуль (сетка 5×5, 4 типа тайлов, свайп/клик).
- Языки: RU/EN переключатель (резюме должно жить и без перевода — контент пишется на RU, EN добавляется на этапе полировки).
- Мобильные устройства — обязательно (HR откроет с телефона).

**Структура репозитория:**
```
CV_Stark_Games/
  PLAN.md            ← этот файл
  docs/GDD.md        ← гейм-дизайн-документ резюме (1 страница)
  docs/content.md    ← весь текстовый контент резюме (данные кандидата)
  src/               ← index.html, css/, js/
  assets/            ← графика, шрифты
```

**Хостинг:** GitHub Pages (бесплатно, стабильная ссылка). В письмо HR: ссылка + PDF-резюме вложением + 3–4 предложения сопроводительного.

## 4. Неотъемлемые ограничения дизайна

1. **Тайминг:** полное прохождение 3–5 минут; каждая секция имеет «показать сразу» (skip).
2. **Суть до игры:** в первые 3 секунды видно имя, роль, топ-3 навыка и кнопку «перейти к контактам».
3. **Пуск-экран:** короткий, с выбором «Играть» / «Просто резюме».
4. **Без звука по умолчанию**, без автоплея анимаций, уважение к prefers-reduced-motion.
5. **Тон:** с любовью к их играм, без панибратства; пасхалки, а не шутки-кринж.

## 5. Этапы работ

| # | Этап | Результат |
|---|---|---|
| 0 | Сбор контента | Опыт, проекты, навыки, достижения, контакты → docs/content.md |
| 1 | GDD + wireframes | docs/GDD.md: структура экранов, маппинг механик, тексты блоков |
| 2 | Каркас | Хаб + мир 1 (RPG-блок) на реальном контенте, статичная вёрстка |
| 3 | Миры 2–3 | Матч-3 механика + финальная сцена с контактами |
| 4 | Полировка | Анимации, «режим дизайнера», мобильная версия, RU/EN |
| 5 | Релиз | Хостинг, PDF-версия, сопроводительное письмо для hr@stark.games |

Оценка объёма: этапы 2–4 — примерно 3–5 вечеров работы, MVP (без EN и без режима дизайнера) можно показать уже после этапа 3.
